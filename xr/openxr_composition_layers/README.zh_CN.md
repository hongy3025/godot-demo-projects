# OpenXR 合成层演示

这是一个 OpenXR 项目的演示，展示了新的合成层功能。
这是[OpenXR 合成层手册页面](https://docs.godotengine.org/en/latest/tutorials/xr/openxr_composition_layers.html)的配套示例。

语言：GDScript
渲染器：Compatibility
最低 Godot 版本：4.3

## 工作原理

合成层允许我们在头戴设备上呈现正常 3D 渲染结果之外的额外内容。
在 XR 中，我们以更高分辨率渲染 3D 图像，然后对其进行镜头畸变处理，再显示在头戴设备上。
这是为了抵消大多数 XR 头戴设备镜头引起的自然桶形畸变。

当我们查看渲染文本或其他主要显示在虚拟屏幕上的 2D 元素时，
这会在采样数据时造成双重打击。
随后的质量损失常常使文本无法阅读，或至少看起来很难看。

然而，事实证明，当 2D 界面呈现在用户面前的虚拟屏幕上时，
通常是一个矩形或略微弯曲的屏幕，
在镜头畸变的 3D 渲染之上渲染此内容，
并简单地将这个 2D 平面弯曲，
就能产生高质量的渲染效果。

OpenXR 支持三种这样的形状，适当使用时可以获得清晰的 2D 视觉效果。
此演示展示了其中一种形状——equirect，一种弯曲的显示屏。

这种方法的唯一缺点是合成发生在 XR 运行时中，
因此屏幕上显示的任何旁观者视图将省略这些层。

> 注意，如果 XR 运行时不支持合成层，
> Godot 会退回到在正常的 3D 渲染结果中渲染内容。

## 动作映射

此项目不使用默认的动作映射，而是配置了一个仅包含此示例所需动作的动作映射。
这样我们可以去除所有杂乱内容，专注于所展示的功能。

此示例只需要三个动作：
- aim_pose 用于定位 XR 控制器，
- select 用于与 UI 交互，它对扳机做出反应，
- haptic 用于在玩家按下扳机时在控制器上发出脉冲。

瞄准 2D UI 将根据你指向的位置模拟鼠标移动。
一次只有一个控制器会与 UI 交互，因为我们只能模拟一个鼠标光标。
你可以通过按下想要使用的控制器上的扳机，在左右控制器之间切换。

鉴于本示例的简单性，我们仅为简单控制器提供绑定。
XR 运行时应该提供适当的重新映射，并且由于使用控制器时简单控制器是强制支持的，
这应该可以在任何 XR 运行时上工作。
在某些系统上，简单控制器也支持手部追踪，在这些系统上你可以使用捏合手势
（将拇指和食指触碰在一起）与 UI 交互。

## 在 PCVR 上运行

此项目可以像普通 PCVR 项目一样运行。确保已安装 OpenXR 运行时。
此项目已使用 Oculus 客户端和 SteamVR OpenXR 运行时测试。
请注意，Godot 目前无法使用 WMR OpenXR 运行时运行。请安装带 WMR 支持的 SteamVR。

## 在独立 VR 上运行

你必须安装 Android 构建模板和 OpenXR vendors 插件，并为你的设备配置导出模板。
请按照[手册中关于部署到 Android 的说明](https://docs.godotengine.org/en/stable/tutorials/xr/deploying_to_android.html)操作。
