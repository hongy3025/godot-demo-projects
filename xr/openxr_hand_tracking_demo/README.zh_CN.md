# XR 手部追踪演示

这是一个展示 OpenXR 手部追踪和控制器追踪逻辑的演示。

语言：GDScript

渲染器：Compatibility

>
> 此演示需要 Godot 4.4 或更高版本

## 工作原理

能够看到玩家的手，并让这些手与环境中的元素交互，对于良好的 XR 体验至关重要。

在此演示中，我们研究了现成的逻辑，用于显示基于控制器输入或通过光学追踪玩家手部自动化的手部模型。
我们还实现了基于动作映射输入的交互逻辑，允许用户拾取此演示中的方块。

这给我们带来的问题是，关于手部追踪的实际含义存在两种不同的思路，
并且根据使用的 XR 运行时，功能可能存在差距。

### 手部追踪仅用于光学追踪

第一种思路将手部追踪视为一个独立的系统，纯粹专注于光学手部追踪。
OpenXR 中的手部追踪 API，即使报告为支持，也仅在光学手部追踪使用时提供数据。

这意味着当使用控制器时，没有数据可用，作为开发者你必须自己提出
显示手部网格并根据控制器输入进行动画处理的解决方案。
请注意，当前版本的 Godot XR Tools 包含一个完整的解决方案。

同样，在这种思路下，动作映射仅适用于控制器输入。
作为开发者，你有责任在光学手部追踪激活时实现某种手势识别方法。

当需要在单个应用程序中同时支持控制器追踪和光学手部追踪时，
这变得尤为棘手。

### 统一方法

第二种思路忽略了控制器追踪和光学手部追踪之间的差异，
将它们视为同一事物的两个版本。
特别是对于 Valve Index 等控制器，或被视为控制器的各种数据手套，
这里没有可辨别的差异。

手部追踪 API 主要用于可视化玩家的手，骨骼位置要么从控制器输入推断，
要么匹配光学追踪。
对于高级手势识别，你仍然会使用这些数据，但现在无论数据获取的物理方式如何，
都可以访问这些数据。

同时，在这种思路下，动作映射系统被视为获取输入的主要手段，
不再局限于控制器的输入。XR 运行时现在负责识别基本手势，
如捏合和指向，产生可以在动作映射中绑定的输入。

OpenXR 正在朝着这种方法发展，此演示也是按照这种方法构建的，但并非所有运行时都已更新。

SteamVR 长期以来一直遵循这种方法，开箱即用，但 SteamVR 将所有内容视为控制器，
导致在通过 Meta Link 或 Steam Link 使用 Quest 并启用光学手部追踪时存在一些缺点。

Meta 的原生 Quest 运行时在所有版本的 Quest 上都支持 OpenXR 的"数据源扩展"，Godot 在手部追踪启用时会启用该扩展。
然而，Meta 尚不支持所需的 OpenXR"手部交互配置文件扩展"。

Meta Link 仍然落后，尚不支持这个新世界。

对于其他运行时，如 Pico、HTC、Varjo、Magic Leap 等，可能支持也可能不支持所需的扩展。

### 结论

由于 XR 运行时能力的快速增长，
并且没有可靠的方法来检测当前平台的全部限制，
Godot XR Tools 不支持手部追踪 API，完全依赖其自己推断的手部定位方法。

然而，随着越来越多的运行时采用这些新扩展，任何针对支持平台解决方案的目标，
都越来越有可能依赖手部追踪 API。

此演示项目展示了那个未来的样子。

## 手部追踪 API

如前所述，手部追踪 API 是可视化用户手的核心。
在 Godot 4.3 中，我们重构了系统，使 XR 接口需要将手部追踪数据转换为 Godot 人体骨骼手部骨骼布局。
这也意味着此逻辑在 WebXR、OpenXR 和任何其他支持此功能的 XR 接口中都能工作。

手部追踪现在也利用了 Godot 4.3 中新的骨骼修饰器逻辑，
但骨骼是在手的局部空间中摆姿势，而定位通过 XRNode3D 节点提供。

这种分离的原因是：

* 定位始终在 XROrigin3D 节点的局部空间内
* 有许多用例可能需要忽略或修改定位

> [!NOTE]
>
> 手部追踪 API 使用的追踪器是 `/user/hand_tracker/left`
> 和 `/user/hand_tracker/right`。

> [!NOTE]
>
> Godot 4.4 中有新的项目设置。
> 如果你将此项目升级到 Godot 4.4 或更高版本，
> 你需要打开项目设置窗口，
> 进入 OpenXR 设置
> 并启用手部追踪源扩展。

## （半）身体追踪 API

这只是顺便提一下，这不是本演示的一部分，但 Godot 现在也支持
包含手部追踪的半身和全身追踪。然而，此功能仅在
有限的 XR 运行时上可用。

## 回退骨骼修饰器

如果 XR 运行时不支持手部追踪，或不支持控制器数据源，
此演示实现了一个回退修饰器，根据动作映射中的扳机
和握持输入来动画化手指。
手的位置现在也基于通过动作映射访问的姿势。

默认情况下，我们使用手掌姿势，这在 OpenXR 动作映射中有正确定义。

由于手掌姿势的支持是可选的，必要时我们会回退到握持姿势。
虽然定位与手掌姿势非常接近，但握持姿势的方向
在不同 XR 运行时之间存在差异，可能导致手部网格对齐不正确。

## 动作映射

如前所述，我们在此处使用动作映射进行输入，但当使用光学手部追踪时，
我们依赖 OpenXR 的手部交互配置文件扩展。
如果不支持此扩展，此演示将无法完全正常运行。

这可以通过检查没有交互配置文件绑定到我们的 XRController3D 节点，
并执行我们自己的手势检测来解决。
由于这会大大增加此演示的复杂性，并且预计此扩展
将很快得到广泛采用，因此本演示中省略了这一点。

> 某些头戴设备在手部追踪启用时会支持简单控制器。
> 简单控制器交互配置文件不支持抓取输入。
> 在这种情况下，你可以使用捏合手势抓取方块
>（将拇指尖与食指尖触碰）。

我们没有使用默认的动作映射，而是创建了一个特定于此用例的动作映射。

此示例需要多个动作：
- `palm_pose` 默认用于定位 XRController3D 节点和我们的手部回退。
- `grip_pose` 在手掌姿势不受支持时使用。
- `pickup` 用作拾取对象的输入，并进行相应映射。
- `trigger` 仅用于动画化我们的食指。
- `haptic` 目前未在演示中使用，但为将来使用而定义。

拾取逻辑本身分为两个组件：

* `pickup_handler.gd/.tscn` 是一个 Area3D 节点，带有逻辑，作为 XRController3D 节点的子节点添加，处理该手拾取范围内对象的逻辑。
* `pickup_able_body.gd` 是一个可以添加到 RigidBody3D 节点的脚本，使该对象可以被拾取/放下。

> 注意，动作映射使用的追踪器是 `left_hand` 和 `right_hand`。

### MSFT 手部交互扩展

微软引入了一个手部交互扩展，Godot 现在支持并已为此项目配置。
其他几个供应商（如 Meta）也添加了对该扩展的支持。

使用此扩展，抓取手势和捏合手势都受支持，因此你可以通过做出抓取动作（握拳）来拾取此项目中的方块。

### HTC 手部交互扩展

HTC 引入了一个手部交互扩展，Godot 现在支持，但尚未在此项目中实现。
此扩展引入了两个新的追踪器，需要你更改 XRController3D 节点上的追踪器才能使其工作。

## 本地地板参考空间

最后一个值得注意的元素是，此演示使用了本地地板参考空间。

使用此参考空间，当用户触发重置中心逻辑时，XR 运行时会将玩家居中在 XROrigin3D 节点上。
启动行为在不同 XR 运行时之间有所不同，Quest 会尝试记住你上次重置中心的位置，而 SteamVR 倾向于将其重置为默认值。
因此，无法保证玩家在演示启动时处于正确位置。
因此建议用户重置中心。

## 在 PCVR 上运行

此项目可以像普通 PCVR 项目一样运行。确保已安装 OpenXR 运行时。
此项目已使用 Oculus 客户端和 SteamVR OpenXR 运行时测试。
请注意，Godot 目前无法使用 WMR OpenXR 运行时运行。请安装带 WMR 支持的 SteamVR。

## 在独立 VR 上运行

你必须安装 Android 构建模板和 OpenXR 加载器插件，并为你的设备配置导出模板。
请按照[手册中关于部署到 Android 的说明](https://docs.godotengine.org/en/stable/tutorials/xr/deploying_to_android.html)操作。
