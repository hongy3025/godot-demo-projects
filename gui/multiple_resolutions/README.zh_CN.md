# 多分辨率与宽高比

**注意：** 此演示旨在展示 Godot 在支持多分辨率和宽高比方面的能力。因此，此演示功能非常全面，但也相当复杂。

如果你赶时间，想在你的游戏中实现*尚可*的多分辨率和宽高比支持，请参阅[多分辨率速成课程](#多分辨率速成课程)。

___

本项目演示了如何设置项目以处理多种分辨率和宽高比的屏幕。

此演示允许你调整窗口的基础分辨率、拉伸模式、拉伸宽高比和缩放因子（内部称为"stretch shrink"）。这让你可以观察调整这些属性时会发生什么。请务必向任意方向调整项目窗口的大小，以查看不同拉伸模式和拉伸宽高比设置下的差异。

GUI 可以适应窗口，也可以从常见宽高比列表中约束为特定宽高比。在超宽宽高比下，这可用于防止 HUD 元素过于分散，从而影响游戏体验。对于非必要的 HUD 元素，特定控件可以在合理的情况下忽略此宽高比约束（例如屏幕侧面的玩家列表）。

此外，还提供了 GUI 边距设置，以更好地处理具有过扫描区域的电视，防止 GUI 元素被裁剪。这也可以在大显示器上通过将 HUD 元素拉近屏幕中心来改善游戏体验。

还使用了具有多通道有符号距离场（MSDF）渲染的 DynamicFont。这可以在任何分辨率下实现清晰的字体渲染，而无需在字号改变时重新栅格化字体。这使得更改此演示中的各种设置更快，尤其是在 GUI 缩放因子设置增大导致使用大字号时。

请注意，默认情况下，Godot 对传统栅格化 DynamicFont 使用字体过采样。这意味着 MSDF 字体*不是*在高分辨率下获得清晰字体的必要条件。

语言：GDScript

渲染器：Compatibility

## 技术说明

此演示使用以下项目设置：

- `canvas_items` 拉伸模式（在 Godot 3.x 中称为 `2d`）。推荐用于大多数非像素艺术游戏。
- `expand` 拉伸宽高比（支持多种宽高比而不会变形或出现黑边）。
- 使用 1:1 宽高比的基础窗口大小（此演示中为 `648×648`）。这可以防止 GUI 元素自动缩小，即使在竖屏模式下也是如此。
  - 使用此设置时，为防止 GUI 在窄宽高比下出现问题，GUI 必须设计为适用于 1:1 宽高比。这在大多数复杂游戏中不可行，因此可以使用宽高比更宽的基础窗口大小（例如 4:3 或 16:10）。宽高比越宽，设计越容易，但 GUI 在窄宽高比下会自动变小，除非用户使用拉伸缩放设置覆盖其缩放比例。许多设备（如 Steam Deck 和 MacBook）采用 16:10 显示屏，因此建议使用 16:10 或更窄的分辨率作为基础窗口大小，以确保在这些设备上开箱即用获得良好的游戏体验。
- 使用 16:9 宽高比的窗口大小覆盖（此演示中为 `1152×648`）。这样，即使基础窗口大小是 1:1 宽高比，项目也会以 16:9 窗口启动。
  - 测试窗口的高度与基础窗口大小的宽度和高度匹配，因此 GUI 元素的大小保持不变。

## 多分辨率速成课程

**此演示中的内容并非对所有游戏都至关重要。** 对于游戏开发大赛项目或手机游戏，大部分内容可以跳过。请参阅多分辨率文档中的[常见使用场景](https://docs.godotengine.org/en/stable/tutorials/rendering/multiple_resolutions.html#common-use-case-scenarios)部分。

与上述文档中描述的更简单设置相比，存在一些限制：

- 当宽高比变得比基础窗口大小更窄时，HUD 会缩小。因此，建议使用 16:10 宽高比的基础窗口大小，以防止 HUD 在 Steam Deck 和 MacBook 上缩小。
- 玩家无法定义边距，这在电视上游戏时可能会有问题（因为过扫描可能会遮挡某些 HUD 元素）。可以通过确保整个 HUD 始终有少量边距来解决此问题。可以在根 Control 节点的所有边上将 Margin 属性增加 10-30 像素左右来实现。

如果你要在 Steam 等桌面平台上发布完整的游戏，请考虑按照此演示的建议实现完整支持。你的玩家会感谢你的 :slightly_smiling_face:
